# 挂载错误故障排除指南

## 错误信息
```
Error response from daemon: invalid mount config for type "bind" : bind source path does not exist
```

## 问题原因分析

这个错误通常发生在其他机器上，主要原因包括：

### 1. **环境变量路径配置错误**
- `.env` 文件中的路径使用了硬编码的绝对路径
- 不同机器的项目路径不同
- 环境变量未正确设置

### 2. **目录结构不存在**
- `data/users`、`data/shared-ro`、`data/shared-rw`、`data/groups` 目录不存在
- 目录权限不正确

### 3. **Docker容器启动失败**
- 之前的容器启动失败，导致目录未正确创建
- 容器状态异常

## 解决方案

### 方案一：使用自动配置脚本（推荐）

```bash
# 1. 确保在项目根目录
cd /path/to/ai4s

# 2. 运行自动配置脚本
chmod +x scripts/setup-env.sh
./scripts/setup-env.sh

# 3. 重启服务
docker compose restart ai4s-platform

# 4. 验证配置
./tests/test-user-mount.sh
```

### 方案二：手动配置

```bash
# 1. 获取当前工作目录
CURRENT_DIR=$(pwd)

# 2. 更新.env文件中的路径
sed -i "s|HOST_USERS_PATH=.*|HOST_USERS_PATH=$CURRENT_DIR/data/users|g" .env
sed -i "s|HOST_SHARED_RO_PATH=.*|HOST_SHARED_RO_PATH=$CURRENT_DIR/data/shared-ro|g" .env
sed -i "s|HOST_SHARED_RW_PATH=.*|HOST_SHARED_RW_PATH=$CURRENT_DIR/data/shared-rw|g" .env
sed -i "s|HOST_GROUPS_PATH=.*|HOST_GROUPS_PATH=$CURRENT_DIR/data/groups|g" .env

# 3. 创建必要的目录
mkdir -p data/users data/shared-ro data/shared-rw data/groups
chmod 755 data/users data/shared-ro data/shared-rw data/groups
chmod 777 data/shared-rw

# 4. 重启服务
docker compose restart ai4s-platform
```

### 方案三：完全重置

```bash
# 1. 停止所有服务
docker compose down

# 2. 清理失败的容器
docker ps -a | grep 'Exited' | awk '{print $1}' | xargs docker rm

# 3. 运行自动配置脚本
./scripts/setup-env.sh

# 4. 重新启动服务
docker compose up -d

# 5. 等待服务启动（约30秒）
sleep 30

# 6. 验证配置
./tests/test-user-mount.sh
```

## 验证步骤

### 1. 检查环境变量
```bash
# 检查.env文件中的路径配置
grep "HOST_.*_PATH" .env

# 检查容器内的环境变量
docker exec ai4s-platform-backend env | grep HOST
```

### 2. 检查目录结构
```bash
# 检查宿主机目录
ls -la data/

# 检查容器内挂载点
docker exec ai4s-platform-backend ls -la /app/users/
docker exec ai4s-platform-backend ls -la /shared-ro/
docker exec ai4s-platform-backend ls -la /shared-rw/
docker exec ai4s-platform-backend ls -la /app/groups/
```

### 3. 运行测试脚本
```bash
# 运行用户目录挂载测试
./tests/test-user-mount.sh

# 运行网站访问测试
./tests/test-website-access.sh
```

## 常见问题

### 问题1: 权限不足
```bash
# 解决方案：使用sudo或确保用户有Docker权限
sudo usermod -aG docker $USER
# 重新登录后生效
```

### 问题2: 路径包含特殊字符
```bash
# 解决方案：避免在路径中使用空格或特殊字符
# 建议使用简单的路径，如 /home/user/ai4s
```

### 问题3: Docker服务未启动
```bash
# 解决方案：启动Docker服务
sudo systemctl start docker
sudo systemctl enable docker
```

### 问题4: 磁盘空间不足
```bash
# 检查磁盘空间
df -h

# 清理Docker缓存
docker system prune -a
```

## 预防措施

### 1. **使用相对路径**
在 `.env` 文件中使用 `${PWD}` 或让脚本自动设置绝对路径

### 2. **自动化部署**
使用 `scripts/setup-env.sh` 脚本自动配置环境

### 3. **定期验证**
定期运行测试脚本验证配置是否正确

### 4. **文档记录**
记录每台机器的具体配置，便于排查问题
